# Pipeline Analytics（内部模块）

本模块负责本地网页 Dashboard、跟进队列、投递漏斗、等待时间和策略复盘。它只通过根目录 `SKILL.md` 调用；执行顺序见 `workflows/`。

## 运营记录边界

历史申请台账已逐行导入 `00-个人资料/dashboard/applications.sqlite`，保留原 Excel 表名、行号和原值；其“已提交”标签仍需原始成功凭证核对。自动发现线索的机器状态在 `00-个人资料/applications/automation/leads.json`。每条岗位记录保留稳定 ID；重复岗位可指向主记录，但不删除历史。数据库事件记录每次修改，网页汇总全局指标。

## 状态模型

操作状态使用：`待处理 / 待用户 / 材料已准备 / 投递中 / 已提交 / 跳过 / 受阻 / 待确认提交结果`。

结果阶段使用：`已评估 / 已投递 / 已回复 / 面试 / Offer / 拒绝 / 撤回 / 失效`。只有平台成功页、确认邮件或明确平台状态才算已核验投递。Dashboard 中“已投递 / 等待面试 / 等待结果”三栏表示当前阶段，原则上只勾选一栏；旧记录冲突保留待复核。

## 跟进规则

规则保存在 `00-个人资料/operations/follow-up-rules.md`，用户规则优先。缺省建议：

- 已投递且无回复：约 7 天后首次跟进；最多 2 次未回复跟进，之后转冷；
- 招聘方已回复：需要用户行动时 1 个工作日内提醒；后续间隔通常不少于 3 天；
- 面试后：约 1 个工作日内准备感谢信息；若对方给出结果日期，以该日期为准；
- 拒绝、撤回、失效或用户要求不联系：停止跟进。

节假日、明确招聘时间表、不同国家文化和用户偏好可覆盖默认值。草稿不等于已发送；只有用户确认发送或有外部成功证据后才更新“最近联系”。

## 漏斗分析

按总量、时间段、岗位族、来源、精投/海投、简历版本和公司类型统计：

- 评估数、通过 Knock-out 数、材料完成数、实际投递数；
- 回复数、面试数、Offer 数、拒绝数、撤回/失效数；
- 投递→回复、回复→面试、面试→Offer 的转化率；
- 投递到首次回复、各轮面试到结果的中位等待时间；
- 当前逾期跟进、受阻和长期无变化记录。

分母必须写清楚，样本很小时显示原始计数而非夸大百分比。仍在等待的申请属于删失数据，不能当作零天或拒绝。精投与海投、不同时间窗和岗位族不得无说明混合比较。

## 复盘动作

寻找可执行模式，而不是给候选人贴标签：

- 哪些来源更常产生有效回复；
- 哪些岗位族在 Knock-out 或面试阶段流失；
- 哪份简历被用于何类岗位及其后续结果；
- 哪些表单/ATS 卡点重复出现；
- 跟进是否过早、过晚或过密；
- 公司研究、联系人触达或精投材料是否带来可观察变化。

把结论分为 `有数据支持 / 可能 / 尚无法判断`，同时记录样本范围和替代解释。建议先改变一个变量并定义观察窗口，再更新筛选规则、简历策略或自动化经验。
