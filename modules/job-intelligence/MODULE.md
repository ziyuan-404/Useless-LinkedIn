# Job Intelligence（内部模块）

本模块负责岗位有效性、去重、Knock-out、A–H 评估、公司研究和联系人发现。它只通过根目录 `SKILL.md` 调用。

## 1. 岗位有效性检查

在评估和制作材料前，优先访问原始雇主或 ATS 页面并记录检查时间。

状态定义：

- `有效`：页面可访问，职位内容与申请入口仍存在，未出现关闭提示；
- `失效`：404/410、明确显示已关闭/不再接受申请，或重定向到无对应岗位的通用页面；
- `未知`：登录墙、地区限制、反自动化或暂时故障导致无法判断。

聚合站失效但雇主原始页有效时，以雇主页为准。`未知` 不等于失效；必要时让用户手动核实。已失效岗位只登记来源和原因，不生成定制材料。

## 2. 去重规则

按以下顺序查 dashboard 和当前队列：

1. 招聘编号或 ATS requisition ID 完全一致；
2. 规范化 URL 一致（去掉追踪参数、片段和无意义尾斜杠）；
3. 规范化公司名 + 岗位名 + 地点一致；
4. 90 天内 JD 高度近似，尤其是猎头转载与雇主原始岗位。

分类为：

- `同一岗位`：指向同一招聘编号或有充分证据；
- `疑似重复`：文本近似但来源、地点或编号不完全一致；
- `不同岗位`：同公司同标题但编号、团队、地点或时间明确不同。

疑似项只标记并给出依据，不自动删除、合并或覆盖既有申请。雇主原始链接优先作为主记录，其余链接作为别名保留。

## 3. Knock-out 预检查

只检查真正会使申请无效的硬门槛，并将每项标为 `通过 / 不通过 / 未知 / 不适用`：

- 工作地点、到岗方式和用户可接受的通勤/搬迁范围；
- 合同类型、开始日期、每周节奏和可用性；
- 明确要求的工作许可、合法资格或“不提供担保”；
- 明确写为必需的语言、证书、学位或注册资格；
- 用户运营规则中的排除公司、岗位或条件；
- 已经投递且规则不允许重复申请。

只有 JD 明确要求且候选人事实明确不满足时才判 `不通过`。`优先/加分/最好具备` 不能作为 Knock-out。候选人情况不明时标 `未知` 并询问，不得推断法律身份或用缺少信息代替失败。

输出结论：`PASS / MARGINAL / FAIL / SKIP`。`FAIL/SKIP` 默认停止定制材料与申请操作，除非用户在看过风险后明确要求继续。

## 4. A–H 岗位评估

### A — 岗位画像

概括岗位族、业务领域、核心职责、资历、工作模式、地点、合同、团队信号和一句话结论。区分 JD 明示与推断。

### B — 要求与证据矩阵

先只读 JD，判断每项的重要性，再读取候选人事实匹配证据，避免为了提高匹配而降低要求。默认保留全部关键/高要求，其余总量控制在约 12 项。

| 字段 | 允许值 |
|---|---|
| 重要性 | `关键 / 高 / 有意义 / 加分 / 弱信号` |
| JD 依据 | 原文短语或准确释义 |
| 匹配 | `满足 / 部分 / 相邻 / 缺失 / 未知` |
| 证据强度 | `已明确 / 结构性支持 / 合理推断 / 无证据` |
| 来源 | 经历库文件、母版页码/段落或用户确认时间 |
| 动作 | 写入 CV、动机信解释、面试准备、补问或接受缺口 |

合理推断不能满足 Knock-out、关键或高要求。

### C — 层级与申请策略

判断资历跨度、是否适合精投/海投、材料应突出什么、是否存在过高/过低定位风险，以及投递时机。

### D — 市场与条件

总结薪酬信息、合同、地点、需求信号和公司类型。没有可靠公开来源时不猜薪资；可给需要进一步核实的问题。

### E — 定制计划

列出 CV 需要保留、前置、压缩和删除的经历，关键词如何落到真实证据，以及动机信的 2–3 个核心论点。

### F — 面试准备

列出最可能被追问的能力、对应 STAR/STAR+R 事实、当前证据缺口和需要用户补充的问题。

### G — 岗位可信度与风险

检查发布日期/申请入口、职责和条件是否具体合理、重复发布、招聘冻结或裁员公开信号、地点/福利术语不一致、猎头与雇主信息冲突、岗位标题与实际职责偏差。只陈述信号和来源，不对公司作无证据指控。本部分不用于掩盖候选人匹配缺口。

### H — 申请答案草稿

仅在岗位通过预检查且用户要求准备申请时，基于 answer bank 和已确认事实草拟常见问题。法律身份、签证、薪资、声明和新事实保持待用户确认；低优先级岗位默认不生成长篇答案。

## 5. 总结与决策

评估末尾必须包含：

- Knock-out 结论和未决项；
- 3 个最强匹配证据、3 个最大缺口/风险；
- `1–5` 整体优先级（信息不足则 `无法评分`）；
- `精投 / 海投 / 跳过 / 待用户决定`；
- 下一步及其责任人。

整体分是可解释的判断，不是伪精确算法。B 的要求重要性和 G 的可信度信号单独展示，不机械加总。

## 6. 公司研究

用户要求研究或精投需要公司专属内容时，优先使用公司官网、招聘页、官方公告、产品文档和可信新闻，并记录链接和核实日期。覆盖：

- 公司产品、客户、商业模式和当前战略；
- 最近约 6 个月与岗位相关的变化；
- 团队/工程/产品文化的可验证证据；
- 岗位可能解决的问题、竞争格局和候选人可贡献角度。

将事实、来源、日期和推断分栏。无法核实的企业文化或团队描述不得写入正式材料。

## 7. 联系人发现

优先级：可能的招聘经理 > 负责该领域的招聘人员 > 目标团队同事。对每位候选联系人记录公开姓名、当前职位、公司、来源、核实日期、与岗位的关系和置信度 `高/中/低`。

- 不猜测私人邮箱或未公开联系方式；
- 单一模糊姓名或过期页面不得标为已验证；
- 未能确认其负责该招聘时，称为“可能相关联系人”；
- 联系草稿交给 Application Writing；未经明确授权不得发送。
