# 岗位搜索、发现与收集改造

本说明依据运行代码、配置和回归检查，不以 README 的功能陈述作为实现证据。执行入口为 `runtime/tools/scan.mjs`，由统一 CLI 的 scan 子命令调用；Agent 执行入口见 `workflows/discover-jobs.md`。

## 原有实现与问题

| 实际行为 | 影响 | 改造 |
|---|---|---|
| `(portal.queries || c.queries || []).slice(0,3)` | 后续 query 永远未执行 | 全部显式查询 + 岗位族/合同组合 + 可配置地点组成任务计划 |
| 每来源最多保存 `max_results_per_portal || 40` 条 | 找到的岗位也可能直接丢失 | 保存整页全部岗位；旧数量上限弃用并告警 |
| WTTJ 每查询仅发一次请求，max_hits 既作页大小又有内部数量限制 | 只看第一页，检索窗口无提示 | 逐页读取 nbPages/nbHits，页大小不是总上限；窗口受限明确标记未完成 |
| API 找到匹配岗位就跳过 HTTP | 一个渠道命中会抑制补充发现 | API、列表、来源域名搜索、全网搜索、企业招聘页发现独立任务 |
| 标题必须同时包含合同词、岗位词且无排除词 | 合同或技能写在 JD 的岗位漏收 | 保留已观察岗位，关键词仅给匹配提示，完整 JD 筛选另行执行 |
| fallback query 固定追加 Paris France | 广域搜索被重新收窄 | 地点来自可修改配置，也可用空地点执行无地域关键词搜索 |
| 仅已登记 portal 的 import 会被收集；缺 job_pattern 默认不接受任何 URL | 新平台和企业官网被丢弃 | 任意已观察详情链接可导入；结构化岗位和 IAB 明确岗位证据支持未知路径 |
| 不遍历 HTML/API 分页；读取过 URL 或来源有 API 结果就清掉 fallback | 部分完成被当作全部完成 | 独立任务进度、分页 cursor、来源证据和未完成覆盖统计 |

## 新流程

配置及新发现来源 → 完整任务计划 → 公开 API/HTTP 逐页读取 → 观察到的岗位与来源入库 → IAB/Agent WebSearch 处理剩余任务 → 注册新企业招聘来源 → 继续列表和分页 → 完整 JD 有效性、历史重复与候选人硬条件核验。

- `discovery-plan.mjs` 负责配置校验、查询组合、任务身份、刷新与续跑。来源配置变化使旧任务退役，避免沿用旧过滤条件/页码；退役记录仍保留在队列中。
- `discovery-sources.mjs` 负责公开 Greenhouse、Lever、WTTJ 及通用 JSON API，支持字段路径、page/offset 或 next URL 分页。专用适配器只加速对应平台；其他平台通过通用配置、IAB 观察和导入接入，不要求代码白名单或公司专属脚本。
- `listings.mjs` 读取普通 HTML、JSON-LD 与实际 next 链接，识别外部 ATS 入口。未知链接形态需 IAB 明确岗位证据；不能把导航、人才库、预测招聘企业或培训广告当成岗位。
- `scan.mjs` 按上次执行时间轮转，每轮每任务读取一页，避免大来源或小预算让其他任务饿死。队列、来源与线索持久化；扫描互斥锁防止两个 scan 相互覆盖。
- `leads.json` 对规范化 URL 精确去重，保留所有观察来源、查询、页面和时间。重发现只补空白字段及来源证据，不改写已评估/已提交状态。跨平台疑似重复仍由后续核验处理。
- 请求预算和页数预算可配置，0 表示无限；预算暂停时已经得到的整页完整入库，剩余任务和页码保留。默认工作区每轮 80 次读取、页数不限，Agent 继续 IAB/网页搜索任务，不自动声称全网执行完成。

## 检查与边界

自动回归覆盖第 4/5 条查询、查询组合与地点、105 条结果、未知企业路径、WTTJ 多页及服务端窗口、JSON/HTML 分页、低预算公平续跑、API 与 HTTP 并行渠道、受阻及 IAB 恢复、来源注册、旧任务退役、真实投递状态保护、重复页面停止、SPA 标识和 API 凭证跨域保护。开发工作区运行 `npm run test:discovery`，完整回归用 `npm test`；`USELESS_LINKEDIN_TEST_SKILL` 可让开发工作区的测试验证另一份 Skill 实现。测试只保留在开发工作区，脱敏发布副本不包含测试文件或测试入口；发布副本仍可运行 `npm run check` 和 JavaScript 语法检查。

真实抽查只验证对应来源和路径，不证明所有平台已经逐个验证。必须保留以下边界：

1. 登录墙、CAPTCHA、反自动化、动态列表需 IAB；无法访问时保留 blocked/needs-agent，不标零结果或失效。
2. WTTJ 的 Algolia 接口来自其当前公开客户端环境，属于可变接口；故障或检索窗口受限交网页搜索/按真实过滤维度细分，不能承诺接口永久稳定。
3. 搜索引擎索引存在延迟；无域名搜索和企业发现扩大覆盖，但不能证明全网无遗漏。队列未执行不算搜索已完成。
4. 无分页元数据或明确结束证据时，已有岗位仍保存，任务保持未完成。重复页/服务端检索窗口不会伪装成穷尽结果。
5. 保留更多岗位会增加后续核验量；candidate/review 是发现提示，不是资格结论，更不是投递成功证据。
6. 通用 API 目前面向公开 GET JSON 列表。需要自定义 POST、私有接口或复杂游标协议的站点可用 IAB/Agent 导入；没有为所有 ATS 写专用接口。
7. 请求超时、响应体大小和公网地址检查属于稳定性/访问边界，继续保留；这些限制不会通过裁剪 query 或岗位数组静默丢结果。

公开 API 规范：[Greenhouse Job Board](https://docs.greenhouse.io/job-board.html)、[Lever Postings](https://github.com/lever/postings-api)。
