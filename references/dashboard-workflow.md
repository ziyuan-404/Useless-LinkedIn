# Excel Dashboard 工作流

权威文件是 `WORKSPACE_ROOT/求职Dashboard.xlsx`。使用 Spreadsheets 能力创建和修改，并在保存前重新计算、检查公式错误和目视验证受影响工作表。

## 工作表结构

- `总览`：全局计数、需要用户处理、近期跟进和状态说明。
- 每个有新增或状态变化的日期使用一个 `YYYY-MM-DD` 工作表。
- 日期工作表保存当天处理的岗位；同一岗位后续状态变化时，同时更新原始记录和当天变更记录，避免丢失时间线。

## 日期工作表字段

至少包含：记录 ID、日期、公司名称、申请职位、匹配度、完整 JD、投递模式、使用简历、动机信、已投递、等待面试、等待结果、执行状态、岗位链接、招聘编号、有效性、重复状态、Knock-out、投递渠道、下一步、跟进日期、最近联系、卡点/结果。

三个状态栏使用 `☐/☑` 选择。它们表示当前阶段，原则上只勾选一栏；多栏同时勾选时，执行状态必须显示 `状态冲突`，先修正再汇报。最终拒绝、Offer、撤回或过期写在“卡点/结果”，并取消三栏勾选。

## 执行状态

这些是 Excel 人用视图的中文标签，不是机器状态名：`待处理`、`待用户`、`材料已准备`、`投递中`、`已提交`、`跳过`、`受阻`、`待确认提交结果`。机器状态以 `.career-os/tools/lib/state-machine.mjs` 为准；同步时按实际卡点和证据映射，不能将中文标签直接写入机器状态。只有看到明确提交成功页面或平台状态时才能使用 `已提交` 并勾选“已投递”。

## 更新规则

- 收到 JD 后立即建行，完整 JD 原文不得用摘要替代。
- 保存岗位来源和检查时间；生成材料前完成有效性、去重和 Knock-out。
- 匹配度使用 `高/中/低/延伸`，A–G 分析形成的整体优先级可另记 `1–5`；H 申请回答草稿不计入评分，不要伪造百分比。
- “使用简历”和“动机信”记录实际绝对路径；海投没有动机信时留空。
- 精投材料生成后更新路径和状态；真实提交后更新状态和跟进日期。
- CAPTCHA、登录、敏感问题或上传失败写清具体卡点和用户下一步。
- 任何一次尝试都要留下结果；不能只在成功时记账。

漏斗、跟进和等待时间的口径见 `modules/pipeline-analytics/MODULE.md`。公式不得把空白或仍在等待的申请计为拒绝，疑似重复记录不得在未核实前自动删除。
