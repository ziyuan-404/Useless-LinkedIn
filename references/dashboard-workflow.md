# 本地网页 Dashboard 工作流

双击 `WORKSPACE_ROOT/打开Dashboard.cmd` 同时启动 Dashboard（`127.0.0.1:8765`）和材料编辑器（`127.0.0.1:8766`）；两个服务就绪后会使用系统默认浏览器打开看板，材料编辑器可从看板进入，窗口保持运行并显示两个地址。已有同工作区服务会被复用，窗口启动的服务退出后会尝试恢复；按 Ctrl+C 停止本窗口启动的服务。权威台账是 `个人资料/dashboard/applications.sqlite`；仅监听 `127.0.0.1`，没有云端同步。网页可搜索，按状态与公司首字母筛选，按日期或公司名称正反排序；列表每页可选 10、20 或 50 条，翻页时保留当前筛选。还可新建、编辑、查看统计和历史来源。每次修改保留事件记录与版本号。

概览中的“每日投递”折线图按台账的申请日期和 `已提交` 状态统计最近 21 天，包含尚未核验的历史提交标记；“已核验提交”数字仍只计入有独立成功凭证的记录。
折线图使用同一坐标系绘制刻度与数量，可将鼠标移到图上或用键盘方向键查看单日数字。四个概览数字可点击，分别打开台账中的到期跟进、待用户、提交待核验和已核验提交筛选；点击时清除旧搜索、状态和首字母条件，使列表条数对应概览数字。

界面将待办数字、筛选与申请记录放在主要阅读区域；最近 21 天趋势图保持展开。记录总数和每页条数选择显示在快速查看区域的右侧，与表头分离。状态标签统一尺寸，记录内容垂直居中。快速查看与概览数字都会清除旧搜索、状态与首字母条件，使显示数量对应全局计数。宽窗口中的表头和对应列使用统一的对齐方式，核验图标及文字整体居中于状态标签下方。窄窗口中的记录改为带字段名称的双列布局，查看按钮始终位于面板内，无需横向滚动。保存成功后显示提示；关闭或离开前会保护未保存修改。选择新阶段时取消另外两个阶段，已有历史冲突仍保留到用户主动调整。

看板和材料编辑器可切换中文、英语和法语，选择会在各自页面刷新后保留；从看板打开编辑器时会带上当前语言。界面标签、状态和选项按所选语言显示，台账原值、用户填写的文本和凭证保持原文，以免改动业务记录。

历史 Excel 已只读导入。原表、行号及 23 列原值均保留；旧表中的“已提交”只表示历史标记，尚未逐条核对成功凭证。不要把旧标记直接计为已核验投递。历史阶段勾选冲突保留原值并提示复核。

## 字段与状态

记录包含：稳定 ID、日期、公司名称、申请职位、匹配度、完整 JD、投递模式、使用简历、动机信、已投递、等待面试、等待结果、执行状态、岗位链接、招聘编号、有效性、重复状态、Knock-out、投递渠道、下一步、跟进日期、最近联系、卡点/结果。完整 JD 原文不得用摘要代替；文件路径填写实际绝对路径。

三个阶段栏在界面中使用复选框，台账仍保存 `☐/☑`，新记录与编辑后必须最多勾选一栏。执行状态可以是 `待处理`、`待用户`、`材料已准备`、`投递中`、`待确认提交结果`、`已提交`、`跳过`、`受阻`。这些是人用标签，不是 `leads.json` 的机器状态。网页输入的提交证据文本也不自动变成“已核验”；必须独立核对平台成功页、确认邮件或明确平台状态。机器状态以结构化原件凭证进入 `submitted` 后，工具会同步数据库并计入“已核验提交”；如同步失败可用 `dashboard --sync-submitted LEAD_ID` 重试。

## 操作顺序

收到 JD 后建行，保存完整原文与来源；生成材料前检查岗位有效性、去重和 Knock-out。精投材料完成后填实际 CV / 动机信路径及下一步。点击提交按钮后先记 `待确认提交结果`；看见成功凭证后记录凭证和状态，后续独立核验。CAPTCHA、登录、敏感问题或上传失败记录具体卡点和用户下一步。任何尝试均留下结果，不能只在成功时记账。

### 已核验投递的三个必填运营字段

同步已核验提交时，Dashboard 的 `匹配度`、`下一步`、`跟进日期`都应有值；不得只写提交状态和凭证。

- **匹配度**：Agent 在岗位 `assessment.json` 中单独给出 `matchLevel`（`高 / 中 / 低 / 延伸 / 无法评分`），依据 B 要求与证据及关键缺口判断。`priority` 是投递优先级，不能机械换算成匹配度。旧评估若未记录匹配度，标 `无法评分` 并等待重新评估，不猜数值。
- **跟进日期**：以成功凭证 `observedAt` 的当地日历日期为基准，按 `个人资料/operations/follow-up-rules.md` 或招聘方明确时间表计算。默认已投递无回复约 7 天后检查；有明确安排时在 Dashboard 中覆盖默认日期。已存在的人工日期不得被自动同步覆盖。
- **下一步**：写清目前动作和检查日期，例如 `等待回复；2026-10-03 检查是否需要首次跟进`。不沿用评估阶段的 `生成简历` 或 `准备申请`。首次跟进是检查和准备消息，不代表消息已发送。

同步工具创建记录时写入三个字段；重试同步只补空值，保留已经填写的匹配判断和跟进计划。完成后检查网页列表与数据库记录；若字段为空，按上述证据修复并保留修改事件。

`tracker --history` 从数据库读取链接用于去重；命中历史记录不能证明已提交。跟进、漏斗和等待时间口径见 `modules/pipeline-analytics/MODULE.md`。
