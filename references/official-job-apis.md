# Official job APIs

## France Travail

Create an application in the [official developer portal](https://francetravail.io/produits-partages/catalogue/offres-emploi). Set FRANCE_TRAVAIL_CLIENT_ID and FRANCE_TRAVAIL_CLIENT_SECRET in the process environment or a local secret manager. An existing bearer token can instead be supplied using FRANCE_TRAVAIL_TOKEN. Never add credentials to portals.yml, test fixtures, imports or Git. Missing credentials park the API task without a request; supplying them automatically unlocks the next scan. Open-web fallback remains available meanwhile.

The adapter uses the documented client-credentials endpoint at entreprise.francetravail.fr, scopes `o2dsoffre api_offresdemploiv2`, and the v2 search endpoint. Tokens are cached only in memory, refreshed once after an HTTP 401 and never persisted in reports, page caches or cursors. Authenticated requests reject redirects to another origin, including OAuth form bodies.

The current [v2.01 API reference](https://francetravail.io/produits-partages/catalogue/offres-emploi/documentation#/api-reference/operations/recupererListeOffre) permits at most 150 records per response, with range start <=3000 and end <=3149. This is a provider constraint, not a total collection limit. All configured queries run. Above the provider window, creation-date-descending searches restart at an inclusive older date boundary and deduplicate overlapping postings. An unresolved identical-timestamp window, missing pagination metadata or unrecognized geographic scope remains incomplete; no invented cutoff silently discards jobs.

`api.params.sort: 1` orders creation dates descending. The default France Travail source explicitly enables newest-first stopping on a previously observed unchanged page and a full refresh every 168 hours. Updated dates and descriptions participate in page signatures. An early incremental stop never establishes absence; only a complete later snapshot can mark possiblyClosed. Ordinary HTML and La Bonne Alternance search do not have a proven global newest-first order and remain ineligible for this shortcut.

France and an empty location need no geographic filter. Other configured locations require `api.locations` mapping to documented INSEE commune, departement or region codes, optionally distance. Free-text cities are not silently converted to region codes. Contract and other documented API filters can be supplied in api.params; the adapter does not invent a contract category. France Travail combines natureContrat and typeContrat with OR.

## La Bonne Alternance

Request a key through the [official developer portal](https://api.apprentissage.beta.gouv.fr/en/explorer/recherche-offre), then set LBA_API_TOKEN in the process environment. Both sandbox and production use the official API host, with the appropriate key. The [current OpenAPI document](https://api.apprentissage.beta.gouv.fr/api/documentation/json) is the field/endpoint authority.

The default source uses `api.mode: export`: obtain `/api/job/v1/export` metadata, immediately read its short-lived signed storage URL without forwarding the API bearer token, stream only the jobs array into a replaceable local NDJSON snapshot, then collect configurable batches with durable byte cursors. The complete export avoids the search route's 450-job cap and does not hold the whole JSON document in RAM. Its publisher updates it daily; it is not a real-time vacancy feed. Repeated identical lastUpdate values reuse the existing snapshot without another download or disappearance claims. Local job liveness still needs detail-page verification before processing/applying.

The local snapshot is under the discovery state directory, contains public job data and is excluded from releases. Only declared storage hosts are permitted: the documented OVH regional object-storage hosts by default, or explicit api.export_allowed_hosts. Signed URLs are never written to queues or reports. api.max_export_bytes defaults to 512 MiB and api.export_timeout_ms to 180000; exceeding this configurable transport budget leaves the task incomplete. api.page_size controls a batch, not a total result limit. A partial/broken export is deleted and never acknowledged as complete. Search filters are rejected in export mode rather than silently ignored.

Use `api.mode: search` for structured filters: latitude/longitude together, radius, romes, rncp, target_diploma_level, opco, departements and partners_to_exclude. The search endpoint has no free-text query or pagination; it returns at most 150 jobs from each of three source groups, up to 450. Even fewer results do not prove exhaustion. Search tasks therefore retain a provider coverage warning, activate fallback discovery and refresh on schedule. Provider warnings also prevent a complete claim. Predicted recruiters are separate from actual jobs and never become leads. Filled/Cancelled offers are excluded from active discovery. HTTP 419 is the provider's rate-limit response and uses transient retry/Retry-After handling.

## Optional components and verification boundaries

HTTP defaults to native Node fetch. impit remains an explicit per-source option only; it never imports user sessions, defeats CAPTCHA, or overrides robots/pacing. Playwright provides isolated rendering when needed. For large official feeds this project reuses [stream-json](https://github.com/uhop/stream-json), pinned to 3.7.0, rather than maintaining a custom streaming JSON parser. Existing persistent tasks and journaling remain the single discovery queue; adding Crawlee would duplicate that responsibility.

External tools such as [JobSpy](https://github.com/speedyapply/JobSpy) can export observed records into the existing import contract: an array of url/title/company/portal/location/description/publishedAt, then `scan --import FILE --import-only`. Map JobSpy job_url to url and date_posted to publishedAt. This project neither installs JobSpy by default nor claims that an external collector bypasses provider limits or access challenges. No integration is inferred merely from a site's name appearing in the external project's supported list.

[AnySearch sub-domains](https://www.anysearch.com/docs/api-endpoints/v1-sub-domains) uses repeated domain parameters and may work with anonymous daily quota. Search documentation currently caps a response at ten results and does not document pagination. Keep it optional: a failed capability request cannot establish supported job engines or justify default adoption. Live smoke results belong in the private verification report; snippets still require observed job identity before import.

Explicitly configure discovery.web_backend as anysearch to populate each web-search task's searchSuggestions for Agent verification. By default the backend remains agent. discovery.anysearch supports language, zone, an observed tag/params, and api_token_env for a local key; without a configured key the optional backend uses the documented anonymous allowance. A failing configured key is not silently replaced with anonymous access. All queries remain in the plan; the provider's ten-result response limit is reported, with no invented pagination. Neither search snippets nor listing/training pages are automatically added to leads. Tasks remain needs-agent until detail identity and coverage are reviewed, and transient failures retain the normal retry schedule.

node:sqlite is loaded only when database work is actually needed. Node 24 may emit its experimental-feature warning during those commands; it is retained rather than hiding all experimental warnings. It does not indicate a failed transaction, and no alternate database implementation was added to mask it.

The official-API regression suite uses real loopback HTTP servers, OAuth form validation, authenticated redirect traps, provider range windows, resume checkpoints, complete streaming exports and incremental/absence checks. Existing browser tests launch real Chromium against a dynamic local recruitment site. These tests exercise running components; they are not proof of production access without keys or of every platform's current anti-bot behavior.

JSON API responses use a configurable 128 MiB transport budget (api.max_response_bytes), read with a byte-counted stream. Ordinary HTML retains an 8 MiB budget. Large Greenhouse content=true and Ashby boards can exceed the earlier HTML-sized limit; this transport budget is separate from job counts and leaves oversized tasks incomplete rather than truncating returned records. Complete LBA exports use their separate streaming budget.
